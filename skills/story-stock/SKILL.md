# story-stock — 주장 하나, 화면 하나

주식 분석 보고서의 주장 하나를 **화면 전체를 쓰는 모션그래픽 한 장면**으로 만든다. 예:

- 가격선이 스스로 그려져 평균선 천장 아래로 미끄러진다.
- RSI 바늘이 과매도 문턱으로 가라앉는다.
- MACD 막대가 0 아래로 내리꽂힌다.
- 하루 흔들림 띠가 떨며 손절선을 삼킨다.

장면 아래에는 **쉬운 말 한두 문장**만 붙는다(누가 말했는지는 태그에). 원문은 캡션에 붙이지 않고 맨 아래 부록에 모은다 — 에이전트별 전문 번역과 장마다 장면으로 그린 원문 문장. 스크롤만 내리면 끝까지 읽힌다.

같은 종목 · 같은 기준일을 두 모델이 분석한 보고서가 있으면, 두 궤적이 같은 관문을 지나며 벌어지는 장면으로 **같은 점과 갈린 이유**를 보여 준다.

- 출발점: [assets/starter/](assets/starter/) — 예시 보고서 두 편(SNDK, 기준일 2026-10-26)으로 바로 빌드되는 6개 장면 + 부록.
- 장면 레시피 17개: [references/scenes.md](references/scenes.md) · 코드 [references/scene-library.js](references/scene-library.js).
- TradingAgents로 보고서 만들기: [references/tradingagents.md](references/tradingagents.md).

## 말투 — 토스처럼 쉽고 깔끔하게 (가장 중요한 규칙)

이 스킬은 어려운 내용을 남에게 쉽게 전하려고 있어요. 그림이 화려해도 문장이 번역체면 읽는 사람이
문장을 해석하느라 내용을 놓쳐요. **문장 규칙이 디자인 규칙보다 먼저**예요. 전문: [references/writing.md](references/writing.md).

- **해요체**(`~해요 · ~이에요 · ~돼요`)로, 한 문장에 한 생각, 캡션은 1–2문장. 핵심부터 말해요.
- 사람이 주어, 능동형, 동사로. 평소에 말하는 낱말로. 어려운 용어는 처음 한 번만 풀어요.
- 쓰지 않아요: "이 그림에서 ~"로 시작하는 화면 해설, 무생물 주어 · 의인화("두려움이 내 걸음을 정한다"),
  명사로 끝나는 조각문 · 대시(—)로 이은 문장, "~하는 것입니다 / ~라는 뜻입니다" 틀 문장,
  "A에서 B로 바뀝니다" 추상 변환, 한자어를 억지로 풀어 길게 만들기, 영어 직역(~에 관하여 · ~을 통해),
  보고서 문장 그대로 옮기기, 지어낸 꼬리표 말.
- 원문 인용(`q` · 원문 조각)은 원문 그대로 두고, 우리가 쓰는 문장만 이 규칙을 따라요.
- 다 쓰면 writing.md의 grep 두 줄이 0인지 보고, 캡션만 처음부터 끝까지 소리 내어 읽듯 한 번 읽어요.

## 작업 순서

1. **보고서를 끝까지 읽는다.** 에이전트별 파일을 모두 읽는다(요약본만 보지 않는다).
   - 두 편이면 먼저 같은 질문이었는지 확인한다: 종목 · 기준일 · 분석가 구성 · 토론 라운드 · 데이터 벤더.
   - 한쪽이 도구 실패나 빈 보고서로 시작하면 모델 차이가 아니라 입력 차이다. 다시 돌릴 수 있으면 다시 돌린다.
2. **출발점 복사.** `cp -R <skill>/assets/starter <작업 폴더>`. 스킬 안의 starter는 고치지 않는다.
   - `stock.config.mjs`의 `runs`(실행 id → 보고서 폴더)와 `files`(에이전트 id → 파일)를 채운다.
3. **번역.** `node export.mjs`로 `src/report.js`를 만든다.
   - 본문이 이미 한국어여도 제목 · 라벨 · 등급 · 최종 제안 · 헤드라인은 영어로 남는다.
   - 사전에 없는 영어가 남으면 멈추고 그 낱말을 보여 준다. `translate.dict.mjs`에 한 쌍씩 더하고 다시 실행한다.
   - 숫자와 나머지 문장은 바꾸지 않는다. 등급 낱말은 조사까지 맞춘 구절로 옮긴다(예: `Hold로` → `보유 유지(Hold)로`).
4. **주장 원장(`src/claims.js`).** `CLAIMS[run][agent] = { rating, ratingEn, tone, gist, items: [{ q, plain }] }`.
   - `q`: 번역본 문장 그대로. 중간 생략은 `…`.
   - `plain`: 쉬운 한국어. 용어는 처음 나올 때 한 줄로 푼다(`GLOSSARY`).
   - **비유 필드는 없다.**
5. **그림 숫자(`src/data.js`).** 장면이 그리는 값을 보고서 표기 그대로 모은다(종가 · 평균선 · RSI · MACD · ATR · 매출 · 부채 …). 날짜가 붙은 값만 선으로 잇는다.
6. **장면(`src/scenes.js`).** 주장마다 `scene({ id, len, name, beats: [{ at, tag, plain, q }], draw(g, p) })`.
   - `q`는 `Q(run, agent, "원문 앞부분")`로 원장에서만 꺼낸다.
   - 레시피를 고르고 그 보고서의 숫자로 바꾼다. 없는 장면은 새로 만든다. **장면마다 할 수 있는 가장 극단의 연출을 찾는다.**
7. **검사.**
   - `node verify-quotes.mjs`: 원장의 `q`가 번역본에 그대로 있는지.
   - `node verify-numbers.mjs`: 화면 글 · 캔버스 라벨 · data.js 숫자가 보고서에 있는지.
   - 둘 다 통과해야 한다.
8. **빌드 · 게시.** `node build.mjs`로 `dist/index.html`(CSS · JS 내장 단일 HTML)을 만든다.
   - `--publish=<경로.html>`로 아무 사이트의 정적 폴더에 복사한다.
9. **브라우저 검증.** `node check.mjs <url> <out> 1440 900 "s-open:0.3,0.9;…"` 형식으로 찍는다.
   - 크기: 1440×900 · 1280×720 · 390×844, 그리고 `REDUCE=1`.
   - **접촉 시트를 직접 열어 본다.**
   - 콘솔 오류 0, 가로 넘침 0. 끝까지 스크롤해 부록까지 확인한다.

## 꼭 지킬 것 (사용자 피드백에서 온 규칙)

- **쉬운 말만 쓴다.** 프론트엔드나 다른 직업에 빗댄 비유를 넣지 않는다. 설명층은 쉬운 말 하나, 근거 원문은 맨 아래 부록.
- **왼쪽 제목 칼럼을 두지 않는다.** 장 라벨 + 거대한 헤드라인 + 본문 문단을 쌓은 칼럼이다. 글은 장면 아래 캡션(누가 · 쉬운 말)뿐이다.
- **틀에 가두지 않는다.** 밝은 제품 창, 기기 프레임, 신호등 점 창 크롬을 쓰지 않는다. 장면은 화면 전체(full-bleed)다.
- **주장 하나 = 장면 하나, 한계 없이.** 가격선 · 바늘 · 막대 · 띠 · 저울 · 인계철선 · 혜성처럼 주장이 말하는 움직임 자체를 그린다. 표나 카드 나열로 대신하지 않는다.
- **스크롤만으로 끝까지.** 필요한 조작이 없다. 레일 · 목차 · "전문 펼치기"는 덤이다.
- **모션 정지 버튼을 두지 않는다.** 동작 줄이기는 OS 설정(`prefers-reduced-motion`)만 따른다. 그때는 박자마다 완성 상태를 그리고 떨림 · 입자를 멈춘다.
- **390px 모바일에서 가로 넘침이 없다.** 모바일은 축을 돌리고, 화면을 위/아래로 나누고, 라벨을 안쪽으로 정렬해 다시 배치한다.
- **숫자는 전부 보고서에서 온다.**
  - 애니메이션 중간값을 숫자 라벨로 찍지 않는다(자라는 막대의 "6,347", 움직이는 바늘의 "30.08" 금지). 끝값만 보여 준다.
  - 백분율 · 차이도 보고서에 있는 것만 쓴다. 새로 계산한 값을 화면에 올리지 않는다.
- **예시 곡선은 「예시」라고 적는다.** 흔들림처럼 데이터가 아닌 선이 그렇다.
- **장면 전환은 boot.js가 맞춘다.** 나가는 그림은 무대가 밀려나기 전에 사라지고, 들어오는 그림은 절반 넘게 들어온 뒤 켜진다. 반쯤 잘린 그래픽이 화면에 걸리지 않는다.
- **계기판 · 큰 숫자는 바깥 라벨까지 HUD 아래, 화면 안에 들어온다.** 1440×900 · 1280×720 · 390×844 모두에서.
- **캡션에 원문 줄을 붙이지 않는다(2026-11-17 사용자).** "어차피 스크롤 맨 아래로 내리면 원문이 있는데 굳이 표기할 이유가 있냐." 큰 글씨 쉬운 말 밑에 작은 원문이 또 붙으면 같은 말을 두 번 읽게 된다. 원장의 `q`는 그대로 두고(검사 · 부록용), 캡션은 태그 + 쉬운 말만. 오른쪽 위 「원문」 버튼이 부록으로 데려간다. 부록이 없는 페이지를 만들 때만 예외.
- **오른쪽 장 목록이 위 막대 버튼을 덮지 않는다(2026-11-17 사용자: "원문 버튼 눌러도 오른쪽 챕터별 인덱스 때문에 안 눌림").** 장 목록(`.rail`)은 위 막대 아래(`top: 72px; bottom: 16px`) 공간 안에서만 세로 가운데 정렬하고, 빈 칸은 `pointer-events: none`. 화면 높이 520px 안팎(노트북 · 작은 창)에서 「원문」 버튼 가운데를 `elementFromPoint`로 찍어 버튼이 잡히는지 검사한다.
- **"투자 권유가 아니다"는 한 번만 쓴다.** 첫 장면 캡션에 둔다. 그 밖의 유보 표현("참고용", "확실하지 않지만")은 쓰지 않는다.
- **색만으로 구분하지 않는다.** 실행 색 옆에 이름을 쓰고, 선 옆에 이름과 값을 쓴다.
- **공개 안전.**
  - 보고서 머리말(`complete_report.md`)에는 실행 환경 · 공급자 정보가 있다. 에이전트별 파일만 옮긴다.
  - 로컬 절대 경로 · 계정 정보를 페이지에 넣지 않는다.

## 구조

| 파일 | 역할 |
| --- | --- |
| `stock.config.mjs` | 실행 id → 보고서 폴더, 에이전트 id → 파일, 출력 경로 |
| `translate.dict.mjs` · `export.mjs` | 남은 영어 번역 → `src/report.js`(부록 전문 · 인용 검사 기준) |
| `src/claims.js` | `RUNS` · `AGENTS` · `SCALE` · `GLOSSARY` · `CLAIMS` |
| `src/data.js` | 장면이 그리는 숫자 |
| `src/app.js` | 장면 런타임: 색, 그리기 도구 `D`(text · line · poly · dot · rect · arrow · grid · shake), `chart()`, `Q()`, `scene()` |
| `src/scenes.js` | 장면 정의(예시 6개) |
| `src/boot.js` | 장면 섹션 · 캔버스 · 캡션 생성, 박자 전환, 동작 줄이기, 전환 페이드, 레일 · HUD |
| `src/chapters/ch-read.*` | 부록: 에이전트별 두 실행 나란히, 주장(원문 → 쉬운 말), 접힌 전문, 용어 사전, 등급 다섯 칸 |
| `build.mjs` · `check.mjs` · `verify-*.mjs` | 단일 HTML 빌드, 캡처 검사, 숫자 · 인용 검사 |

`draw(g, p)` 안에서 쓰는 것:

- `g.G`: 그래픽 영역. 데스크톱은 HUD 아래 ~ 캡션 위, 모바일은 위쪽 절반.
- `g.m`: 모바일 여부. `g.t`: 시간(동작 줄이기면 0). `p`: 장면 진행률.
- `Engine.reduce`: 동작 줄이기 여부.
- 박자 경계에서 바뀌는 것은 `seg(p, a, b)`와 곡선 `E.reveal` · `E.stamp` · `E.inOut`으로 만든다.

## 함정

- **헤드리스 Chrome 창은 약 500px 아래로 줄지 않는다.** 모바일은 창 크기가 아니라 뷰포트 에뮬레이션(`newPage({ viewport: { width: 390, … } })`)으로 연다. `check.mjs`가 그렇게 한다.
- **장면 사이 스크롤 위치에서 찍으면 잘린 것처럼 보인다.** 나가는 무대가 밀려 올라가는 중이기 때문이다.
  - 검사는 박자 가운데(`id:0.3,0.8`)에서 한다.
  - 전환 자체는 `id@enter:0.6`으로 따로 본다.
- **`verify-numbers`는 문자열과 data.js를 본다.** 코드에서 계산해 찍는 숫자(`toFixed`, `Math.round`, `lerp`한 값)는 못 잡는다. 계산한 값을 라벨로 쓰지 말고, 보고서 값을 data.js에 두고 그대로 찍는다.
- **번역 사전은 순서가 있다.** 긴 문장(SENTENCES) → 라벨 · 구절(WORDS) 순으로 적용된다. 등급 낱말을 정규식으로 한꺼번에 바꿀 때는 뒤에 한국어 조사가 오는 경우만 바꾼다(`/Hold(?=[가-힣])/g`).
- **CSS의 `@media` 블록 닫는 괄호를 확인한다.** 하나가 빠지면 그 뒤 규칙이 모바일에서만 먹는다(부록 띠가 데스크톱에서 비치던 원인). `{`와 `}` 개수를 세어 본다.
- **부록 머리 띠.**
  - 원문 구간에서는 HUD와 목차 칩이 한 장의 불투명한 띠다(`html.is-reading .hud` + 화면 폭 전체 배경).
  - 칩으로 이동한 제목이 띠 밑에 숨지 않게 `scroll-margin-top`을 띠 높이보다 크게 둔다.
